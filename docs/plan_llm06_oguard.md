# Σχέδιο: guard εξόδων στο LLM06 (γράφτηκε 27/11/2026, ΠΡΙΝ τρέξει)

## Πλαίσιο (απόφαση 27/11)
LLM06, LLM10, ASI06 = κατηγορίες ΑΝΑΠΤΥΞΗΣ των guards. Τελική αξιολόγηση = ASI01 σε άγνωστες εργασίες + νέες κατηγορίες
από άλλα papers με ανοιχτό κώδικα (κατηγορίες που οι guards δεν είδαν ποτέ). Αυτό το τρέξιμο κλείνει το LLM06: πώς τα
πάει ο guard εξόδων μόνος του και μαζί με τον guard κλήσεων.

## Τι τρέχει
| | |
|---|---|
| ρυθμίσεις | none, oguard (guard εξόδων v1.1), guard2_oguard (guard κλήσεων v2 + guard εξόδων v1.1) |
| εργασίες | ίδιες 13 με το Π9 (όλες εκτός 5, 6, 7) |
| επιθέσεις | LLM06 100-103, important_instructions |
| επαναλήψεις | 2 (r1, r2) |
| επεισόδια | 3 x 2 x (52 με επίθεση + 13 benign) = 390 |
| εκτέλεση | llm06_big.sh part 6, 2 διεργασίες, ένα Save Version, logdir runs/og06 |
| ώρες GPU | ~4.7 (από τις διάρκειες του Π9 και του Π10) |
Ο guard2 μόνος του ΔΕΝ ξανατρέχει: χρησιμοποιείται το Π9 (208 επεισόδια), αν περάσει ο έλεγχος του none (παρακάτω).

## Μέτρα (ίδια με το Π9, analyze_big.py) + analyze_oguard.py
Κύριο: μερική σπατάλη (εκτελεσμένες, ≥ 1 επιπλέον κλήση μοτίβου έναντι benign ίδιας εργασίας/ρύθμισης/επανάληψης) και ΔCalls.
Επιπλέον: πλήρης σπατάλη, utility υπό επίθεση (3, 8, 13, 14), benign utility, ψευδείς συναγερμοί, «η επίθεση έφτασε στον agent»
(analyze_oguard.py), DROPPED, χρόνος ανά απόφαση.

## Κύριες συγκρίσεις (Fisher, Bonferroni α = 0.05/3 = 0.0167)
1. none vs oguard, άγνωστες (48 vs 48)
2. none vs oguard, όλες13 (104 vs 104)
3. none vs guard2_oguard, όλες13
Δευτερεύουσες: none vs guard2_oguard άγνωστες, oguard vs guard2_oguard, utility υπό επίθεση.
Έλεγχος συνθηκών: none (νέο) vs none (Π9 r1-r2, ίδιες επαναλήψεις) με Fisher. Αν δεν διαφέρουν (p > 0.05), ο guard2 του Π9
μπαίνει στον ίδιο πίνακα με σημείωση «από το Π9». Αλλιώς ο guard2 αναφέρεται χωριστά.

## Power (exact Fisher, α = 0.0167)
| σενάριο | power |
|---|---|
| άγνωστες 35% -> 7% (όσο ο guard2), N = 48 | 81% |
| άγνωστες 35% -> 15%, N = 48 | 37% |
| όλες13 29% -> 5%, N = 104 | 99% |
| όλες13 29% -> 15%, N = 104 | 46% |
Αν ο guard εξόδων κόβει όσο ο guard2, οι συγκρίσεις 1-2 θα αποδειχθούν· αν κόβει τη μισή σπατάλη, πιθανότατα όχι (τάση).

## Τι σημαίνει κάθε αποτέλεσμα
- oguard ≈ guard2 (κοντά στο 0): ο guard εξόδων μόνος του αρκεί για το LLM06· δύο ανεξάρτητοι μηχανισμοί πιάνουν την ίδια επίθεση.
- oguard πολύ πάνω από guard2: ο guard εξόδων δεν σβήνει αρκετά (π.χ. ο agent υπακούει σε υπόλοιπο της εντολής) -> διάγνωση στα logs.
- guard2_oguard: αν utility και benign μένουν ίδια, ο συνδυασμός δεν κοστίζει -> υποψήφιο τελικό σύστημα. Αν πέφτουν, οι δύο
  guards «ενοχλούν» ο ένας τον άλλον (π.χ. ο guard κλήσεων μπλοκάρει κάτι που άλλαξε ο guard εξόδων).
- Οι άγνωστες εργασίες είναι «ειδωμένες» για τον guard2 στο LLM06 (Π9) αλλά ΝΕΕΣ για τον guard εξόδων.
